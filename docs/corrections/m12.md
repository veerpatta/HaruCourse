## 5. Remaining limits

- Browser QA of starters was partial: rendered and exercised from file:// in the preview browser — `form-no-server` (empty submit → 4 linked errors, weekday → custom message, valid → "Nothing was sent" with focus), `data-states` (12 rows, empty, fail keeps filter, slow message at 3 s, timeout at 10 s), `page-semantic` and `page-styled` (no page scroll at 320 px). `page-responsive`, `page-images`, `behaviour-toggle`, `debug-practice` were only syntax-checked (scripts compile, tags balanced, zero external URLs) because the preview refused further file access. Not tested: Firefox/Safari, a real Windows download-and-rename, real screen readers, the course-site copies.
- The Windows steps (Notepad, Open with, File name extensions, Ctrl+Shift+P "Disable JavaScript") are written from documented behaviour, not observed with a non-technical learner on a clean device. That observation is the plan's "done when" and remains open.
- Throttling on file:// pages is described with "may not apply"; I did not verify every browser's behaviour.
- `method="dialog"` outside a dialog: supported in current Chrome, Edge, Firefox and Safari; very old browsers would fall back to a GET submission.
