## Common instructions for every row

- Start from the module's stated destination and existing prerequisite artifact. If missing, show an authored, labelled starter; do not pretend it is the learner's prior work.
- Introduce the listed words in plain language, with an example and a non-example. The list is a starting point, not a complete glossary audit.
- Turn the proposed demonstration into a visible explanation of a decision, then one supported attempt and an independent variation.
- Keep a named recommended workspace, verified controls where applicable, expected result, common-failure recovery and save/reopen instructions beside the task.
- The AI code selects one optional conversation family. Author its actual prompt, fixed practice material, misconception, help, stop and return link; never publish the recipe or an unfilled template.
- Provide the full equivalent local example/practice/feedback route defined for that family. AI skip does not reduce progress or prevent finishing.
- Map the return task to existing answer/repair IDs with unchanged meaning. Where an exact ID is not named here, the author must resolve and record it from the lesson source before implementation; a prose suggestion is not a persistence binding.
- Review all original outputs, not just the small opening task. Preserve scope while making meaningful pause points. Mark observation, independent work, AI rehearsal, simulation and actual research accurately.
- Record Drafted, Content checked, Interface checked, Learner observed and Released independently in the existing audit/ledger with dates and evidence. These entries begin at Planned.
