What this lab is

Step-by-step instructions for two checks you can run yourself: moving through a page with the keyboard only, and listening to it with the screen reader already on your device. It gives the start, stop and pause controls for Windows, Mac, iPhone, iPad and Android.

Practise on this page first. It has headings, a list of links and named regions, so every command below has something to find. Then run the same checks on your own prototype or on the page your lesson names.

This page makes no network requests, stores nothing and contains no tracking.

How to open it

  • On the course site: this page lives at /labs/m11/ on the same site as the course. If the course is already open, keep the site name in the address bar, replace everything after it with /labs/m11/ and press Enter.
  • As files on your own computer: save this page into a folder (in most browsers Ctrl + S on Windows, Command + S on a Mac, then choose “Web page, HTML only” if asked). Open the saved index.html from that folder; it needs no internet connection.

Part 1: keyboard only

This part needs no screen reader. Use a computer, or a phone or tablet with a keyboard connected.

Two practice pages: the booking form with six deliberate barriers and the same form repaired. Try the barrier version first, write down each problem you meet, then compare with the repaired one.

  1. Open the page you are checking: the practice form with barriers first, then your own prototype or the page your lesson names.
  2. Put the mouse out of reach, or keep your hands off the trackpad.
  3. Use only these keys: Tab to move forward, Shift + Tab to move back, Space or Enter to press a button, the arrow keys to move between choices in a group, Esc to close something.
  4. Go from the top of the page to the end, and try to complete the one task you chose: reach every link and control, and use each one.
  5. Write down every point where you could not see where you were, could not reach something, or could not go on.
  6. Note what worked as well. A check that found nothing wrong is a result when you write down what you checked.

On a Mac in Safari, Tab skips buttons and links until you turn on Safari > Settings > Advanced > “Press Tab to highlight each item on a webpage”. Chrome, Edge and Firefox do not need this.

Part 2: with a screen reader

Learn how to stop it before you start it. A screen reader starts talking straight away, and on phones it changes how touch works. Read the controls for your device first, and set up the on/off shortcut before you switch the reader on.

Use the reader that is already on your device. You do not need to buy or install anything.

Windows: Narrator (built into Windows)

  • Start or stop: Windows logo key + Ctrl + Enter. Press the same keys again to stop.
  • Narrator key: Caps Lock or Insert. Commands below write it as “Narrator”.
  • Stop it reading: Ctrl. Turn speech off or on: Narrator + Shift + S. Exit: Narrator + Esc.
  • On a web page: scan mode usually turns on by itself in Edge, Chrome and Firefox (Narrator + Spacebar turns it on or off). In scan mode press H for the next heading, K for the next link, F for the next form field, D for the next landmark, and Enter or Spacebar to use the item. Tab still moves between controls.
  • Other way in: Settings > Accessibility > Narrator, or Windows logo key + Ctrl + N to open Narrator settings.

NVDA is a different, free screen reader for Windows that you would have to download and install from NV Access. This lab does not need it. If you already use NVDA: Ctrl stops speech, and NVDA + Q then Enter quits (the NVDA key is Insert).

Mac: VoiceOver

  • Start or stop: Command + F5. If nothing happens, hold Fn as well. On a keyboard with Touch ID: hold Command and quickly press Touch ID three times.
  • VO keys: Control + Option together, or Caps Lock. Commands below write them as “VO”.
  • Pause or resume speech: Control.
  • Move and act: VO + Right Arrow for the next item, VO + Space to press it, VO + Command + H for the next heading, VO + U for the rotor (lists of headings, links and form controls).
  • Other way in: Apple menu > System Settings > Accessibility > VoiceOver.

iPhone or iPad: VoiceOver

  • First, set up the shortcut: Settings > Accessibility > Accessibility Shortcut > VoiceOver. After that, triple-click the side button (or the Home button on models that have one) to turn VoiceOver on or off. You can also ask Siri to “Turn on VoiceOver” or “Turn off VoiceOver”.
  • Important: while VoiceOver is on, touch works differently. Tap once to select and hear an item; double-tap to use it.
  • Move: swipe right for the next item and left for the previous one. Scroll with a three-finger swipe up or down.
  • Pause or continue speaking: two-finger tap.
  • Practise safely: Settings > Accessibility > VoiceOver > VoiceOver Practice lets you try gestures without changing anything.

Android: TalkBack

  • First, set up the shortcut: Settings > Accessibility > TalkBack, then turn on the TalkBack shortcut. After that, press and hold both volume keys for a few seconds to turn TalkBack on or off. You can also say “Hey Google, turn off TalkBack”.
  • Important: while TalkBack is on, touch works differently. Tap once to select and hear an item; double-tap to use it.
  • Move: swipe right for the next item and left for the previous one. Scroll with a two-finger swipe.
  • Pause or resume speech: two-finger tap (TalkBack 9.1 and later on supported phones).
  • Menu names differ between phone makers. If you cannot find a setting, search Settings for “TalkBack”.

What to try

  1. On this page: move heading by heading, then landmark by landmark, then link by link. Do the headings alone tell you what the page holds?
  2. On your own page: move field by field. Is each field announced with its label, and a group of choices with its question?
  3. Find every button. Does each have a name that says what it does?
  4. Complete your task. If a message or error appears, are you told it appeared, and which field it is about?

If the speech is too much

  1. Pause it first: Ctrl on Windows, Control on a Mac, a two-finger tap on a phone.
  2. Then switch it off with the same shortcut you used to switch it on.
  3. On a phone, if gestures stop doing what you expect, use the shortcut you set up (triple-click, or both volume keys), or ask Siri or Google Assistant to turn it off.
  4. Take a break. Ten minutes is plenty for one session, and you can come back.

Part 1 needs no screen reader at all, so you can always do the keyboard test on its own.

What to write in the course

  • Which page you tested, with which device, browser and screen reader (or keyboard only), and for how many minutes.
  • What happened, step by step, in the order it happened.
  • Each failure as what you met, what should have happened, and the decision that caused it.
  • Anything you checked and found working. A clean result counts if you write down what you checked.

What your own session can and cannot show

Your session finds real failures in the page you check, and that is useful. It does not show what disabled people experience. You can see the screen, you know where things are, and you use these tools occasionally rather than every day. Say that in the same place you report what you found.
